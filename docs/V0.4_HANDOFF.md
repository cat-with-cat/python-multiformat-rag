# RAG V0.4.0 Handoff

## Baseline and branch

- V0.3 merge baseline: `1fb0815a23d248651b75c7bd9ca4d531dca24eb6`
- Development branch: `feature/v0.4-rag-agent`
- Release version: `0.4.0`.

## Implemented

- An independent `ChatOpenAI` factory for the configured OpenAI-compatible
  Provider; it does not replace `LLMClient.complete()`.
- The existing `search_knowledge_base` StructuredTool is bound with
  `tool_choice="auto"` and parallel tool calls disabled.
- A small LangGraph model/tool loop with a hard two-call limit.
- Correct `AIMessage.tool_calls` → tool execution → matching `ToolMessage`
  protocol handling.
- Safe rejection of unknown/parallel tools, invalid arguments, malformed model
  responses, tool failures, provider failures, and excessive calls.
- Program-generated source numbering, multi-search deduplication, and final
  citation allowlist validation.
- Deterministic no-evidence refusal without an additional model call.
- System/Human/Tool message separation for untrusted document content.
- API-key fields excluded from `AppConfig` representations.
- LangSmith tracing forced off for Agent invocation, including when ambient
  tracing environment variables are enabled.
- Per-source document text bounded to 8,000 characters before model use.
- Real `ChatOpenAI` HTTP serialization and parsing exercised with an in-memory
  MockTransport; no provider request is sent.
- Python 3.10/3.11/3.12 GitHub Actions matrix with blank API keys and offline
  HuggingFace mode.

## Compatibility

- `RAGService` and `SearchResult`;
- DashScope and OpenAI-compatible text completion adapters;
- LangChain StructuredTool, ChatPromptTemplate, and LCEL chain;
- all existing CLI commands and defaults.

implemented, and the OpenLux result covers only the configured account, model,
route, and three synthetic scenarios.
